> **一个北京正在下雪。**
>

# 02｜基础设施事件：一套正常系统必须被关掉

`LOCKED DIRECTION`

两个区域仍通过一套大型公共环境交换 / 气候交换基础设施存在真实物理耦合。

其可能承担：

- 空气交换；
- 热量交换；
- 湿度 / 水汽交换；
- 大尺度环境循环；
- 其他公共环境平衡功能。

精确工程结构与名称 `TBD / VALIDATE`。

关键不是设备损坏。

相反：

> **设备本身可以仍然完全正常。**

问题在于两个区域已经执行互不兼容的冬季 / 非冬季环境状态。

因此同一套仍然正常的共享环境系统开始把两个局部正确的环境状态物理耦合在一起，并逐步产生危险。

本集核心动作不是“修好它”，而是：

> **主动关闭 / 隔离一套仍然正常的城市级公共基础设施。**

这是“修 → 关”的第一次明确后灾难升级。

# 03｜为什么必须双端同步

`LOCKED DIRECTION`

该环境交换系统不能安全地由一端先关、另一端随后再关。

两端必须在一个很窄的真实物理窗口内完成同步隔离，否则可能产生严重的瞬态冲击，例如：

- 压力失衡；
- 气流 / 热流冲击；
- 水汽凝结 / 结冰；
- 结构或环境系统二次风险。

具体物理机制、允许时间误差与设备逻辑全部 `TBD / VALIDATE`。

宏观要求锁定为：

> **两端必须确认同一个真实物理瞬间，并在该瞬间完成各自那一半隔离动作。**

# 04｜问题不是“钟坏了”，而是没有共同的公共时间

`LOCKED`

两个区域的本地 AI 都会自动维持并校准自己的区域时间。

因此 EP06 不得写成：

> A 区钟坏了 / B 区钟走慢了。

正确逻辑是：

- A 区拥有自洽、可运行的本地“现在”；
- B 区也拥有自洽、可运行的本地“现在”；
- 但两者已经失去一个双方都自动承认、可用于跨区公共动作的共同时间基准。

因此正常的机器间双端同步无法成立。

本集第一次非常具体地提出：

> **如果两个区域连“同时”都无法共同确认，它们怎么完成一个必须同时发生的公共动作？**

`LOCKED`
