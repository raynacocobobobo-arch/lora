# 01｜统一术语

从本 Patch 起，凡当前 Canon、Episode Snapshot、后续 screenplay / storyboard / production docs 中涉及 AI、系统、接口、身份、状态、授权、同步等协议层的 handshake，统一正式术语为：

> **协议握手（protocol handshake）**

不再把技术层单独写成模糊的“握手”，除非是对白中有意保留双关。

---

# 02｜三种“握手/连接”必须区分

## A. 协议握手 / Protocol Handshake

系统/协议层状态确认。

可以涉及：

- 身份；
- 权限；
- 双方准备状态；
- 接口状态；
- 同步条件；
- 版本 / reference；
- 授权关系。

它回答的是：

> **双方在协议意义上是否完成了必要确认。**

它不能自动证明：

> **现实物理通路已经成立。**

## B. 物理连接 / Physical Connection

现实层：

- 人 / 物 / 能量是否真的能通过；
- 结构是否真正对位；
- 两个区域是否在物理条件上实际接触。

EP03 的关键命题统一写为：

> **协议握手完成 ≠ 现实已经连接。**

或英文内部标记：

> **Protocol handshake complete ≠ Reality connected.**

## C. 手 / 身体握手 / Physical Hand Motif

人物身体接触与整季“手”母题：

- EP01：女科长真实抓住男主；
- EP05：重建新人完成牵手 / 戒指 / 仪式接触；
- EP10：私人 AI 伸手，男主无法真实握住。

这一层不能被技术“协议握手”吞掉。

---

# 03｜Handshake Ladder 术语修正

当前梯度在概念上不变，只统一名称：

- EP01：**协议握手 / 身份验证失败 ≠ 现实不存在**；
- EP02：不强塞协议握手母题；
- EP03：**协议握手完成 ≠ 现实已经连接**；
- EP05：手 / 戒指 / 被重建出来的身体接触；
- EP06：**没有共同 reference，就没有可信协议握手 / 同步**；
- EP08：**公共授权协议握手失败**，但更低层 protected-person 约束仍成立；
- EP09：未来共同北京必须定义哪些最低公共状态需要持续可互相确认；
- EP10：执行最终**协议握手**，同时回响人与人“握手 / 抓住”的身体母题。

---

# 04｜EP10 的“握手”台词允许保留双关

当前锁定终局台词方向：

> **“我要去和它握手了。”**

这句话不必改成：

> “我要去和它进行协议握手了。”

因为角色对白需要自然，而且终局本来就有意把：

- 技术上的协议握手；
- 人与人身体上的握手；
- 整季的 Connection 母题；

压在同一句普通词里。

因此：

> **文档技术术语 = 协议握手。**
>
> **终局人物对白可以说“握手”，作为经过前面技术使用后形成的双重含义。**

# 05｜Precedence

本 Patch supersede 当前文档中仅属于**技术命名**的以下旧写法：

- `handshake`；
- `technical handshake`；
- 单独用“握手”指系统协议状态。

它不改变任何既有剧情因果、技术功能或 Hand motif。

若旧 Episode Snapshot 尚未逐字回写，本 Patch 对其技术术语拥有更高解释优先级。
