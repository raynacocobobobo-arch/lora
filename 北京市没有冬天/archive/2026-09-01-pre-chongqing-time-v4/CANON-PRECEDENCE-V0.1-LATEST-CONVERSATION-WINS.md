# 《北京市没有冬天》Canon Precedence V0.1 — LATEST CONVERSATION WINS

- Updated: 2026-08-31
- Status: `LOCKED / CANON GOVERNANCE`
- Purpose: 解决同一设定散落在多个旧 Canon / patch / 对话中的冲突与漏读问题。

## 01｜最高优先级规则

`LOCKED`

当同一事项存在前后冲突时，按以下顺序判定：

1. **同一事项中时间更晚、用户明确确认的对话决定**；
2. 对该决定形成的 **LATEST-CANON-SNAPSHOT**；
3. `CURRENT.md` 中明确写出的 precedence / supersede；
4. 较新的显式 revision / patch；
5. 较早 canonical 文件；
6. 草案、候选方案、未确认讨论。

内部简称：

> **越新的确认，权重越高。**

这不是“新文件自动覆盖旧文件”。只有当新内容明确针对同一事项形成修订时，才 supersede 旧表述。

## 02｜LATEST-CANON-SNAPSHOT 的功能

EP01–EP10 各自建立一份最新权威快照。

它们的功能是：

- 把散落在旧 episode canon、patch、人物 Bible、主题文件和后续对话中的**已确认事实**收束到一处；
- 不要求删除旧文件；
- 旧文件继续保留历史推导、细节和 provenance；
- 若旧文件与最新快照冲突，以最新快照为准；
- 若最新快照没有涉及某个旧细节，且该细节没有被后续否定，则旧 Canon 继续有效。

## 03｜TBD / NEEDS_REVIEW

`LOCKED`

- `TBD` 不得因为整理快照而自动补完；
- `NEEDS_REVIEW` 不得因为整理快照而假装已确认；
- 对话中只是提出、没有得到用户确认的候选方案，不得写成 LOCKED；
- 精确对白、工程协议、编号、机构名称、技术参数，除非已明确确认，否则继续 TBD。

## 04｜对旧 LOCKED Canon 的处理

不得静默删除或改写历史文件。

发生冲突时使用：

> **NARROW REVISION / SUPERSEDE ON CONFLICT**

最新快照应明确说明：只在冲突处覆盖旧表述，其余旧内容继续继承。

## 05｜未来会话读取规则

新 ChatGPT / Codex / Agent 进入项目时：

1. 先读 `CURRENT.md`；
2. 再读本文件；
3. 再读 EP01–EP10 的 `LATEST-CANON-SNAPSHOT`；
4. 需要机制、历史推导、未决问题时，再下钻旧 Canon / patch。

禁止重新从几十个 patch 自行猜测“现在到底哪版有效”。
