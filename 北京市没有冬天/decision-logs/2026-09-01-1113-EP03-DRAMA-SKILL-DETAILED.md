> **握手完成 ≠ 现实已经接上。**

### E. 真正冲突不是“救不救病人”

用户认可：

> **完整公共程序还没恢复，但当前医疗刚需不能等待。**

所以女科长第一次：

> **只根据足够事实，批准一个只对当前行动负责的有限例外。**

不是永久制度设计。

### F. EP03 最大长期新增：成功本身制造未来问题

用户认可的关键结构：

> **正因为这条临时路径真的救了人，它以后才不可能永远只使用一次。**

长期因果：

> 一次成功救援
> → 证明路径有现实公共价值
> → 更多医疗 / 维修 / 生命保障 / 必需物资刚需复用
> → 路径需要持续维护
> → 有容量上限就需要排序
> → 有人员物资流动就需要安全确认
> → 两边分别形成管理流程
> → 临时例外沉积成事实公共走廊
> → EP08 两套公共秩序在同一生命线上重叠。

核心判断：

> **EP08 的问题不是 EP03 失败造成的；恰恰是 EP03 成功以后才有可能出现。**

这与 Master V3.2 的 Preservation Paradox / 隐形社会结构原型吻合。

## Phase B｜Production-oriented Script Pass

然后从 EP01 顺序开始：

> **EP01 screenplay → review → EP02 screenplay → review ...**

不是十集一起写完再看。

每集锁：

- scene IDs；
- visible actions；
- dialogue；
- scene end-state；
- exact opening / ending connection；
- final State Delta；
- final Continuation Capsule。

这里必须开始用“短剧可看性”作为硬标准：

> **Cold Open → Pressure → Turn → Payoff / Progress → Cliffhanger / End Image**

## Phase C｜Storyboard / Continuity Compile

剧本批准后：

> screenplay → asset inventory → continuity compile → fewest readable Shot Specs

遵守：

> **一个 Shot 尽量一个可见动作。**

并建立稳定：

- 角色资产 ID；
- 场景资产 ID；
- 服装 / props；
- 关键帧；
- geography / axis；
- shot start/end state。

## Phase D｜Seedance Production Pack

Shot 验证后：

> valid shots → asset/keyframe readiness → Generation Segments → generation-mode selection → Seedance prompt pack

目标是真正可以交给生成执行器的：

- Generation Segment；
- reference set；
- fixed facts；
- visible action；
- camera / sound policy；
- prompt；
- NOT constraints；
- `READY / BLOCKED / NEEDS_REVIEW`。

如果没有实际视频执行结果：

> **只能到 READY，不能假装 PASS。**
