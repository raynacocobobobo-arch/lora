# 01｜Highest authority

同一事项出现冲突时，按以下顺序判定：

1. **时间更晚、用户对同一事项的明确确认**；
2. 对应 episode 的最高 Active V4 `LATEST-CANON-SNAPSHOT`；
3. `CHONGQING-TIME-MASTER-CANON-V4.md`；
4. `WORLD-ARCHITECTURE-CANON-V4.md` 与 `CHARACTER-RELATIONSHIP-BIBLE-V4.md` 在各自职责范围内；
5. Active execution docs：Visual Bible / Scene Prompt / Teaser；
6. V4 design specs / consistency reports；
7. 旧项目、archive、decision logs 与历史对话记录，仅作 provenance / 非冲突细节来源。

核心原则：

> **更晚的明确确认覆盖同一事项上的旧决定；不是新文件自动覆盖旧文件。**

# 03｜V4 supersession rule

V4 Active 根目录为：

> `重庆时间/`

旧项目根目录及其历史文件保留为 provenance，但在 V4 激活后：

> **不得作为当前事实的默认读取入口。**

旧 Canon 中若存在一个细节：

- V4 没有提及；
- 用户后续没有否定；
- 与 V4 新世界架构没有冲突；

则可以作为候选非冲突细节继续参考，但必须在写入新的 Active 文档前重新确认其与 V4 的兼容性。

禁止因为“旧文件曾 LOCKED”就把已经被 V4 世界重构替换掉的机制重新带回。

---

# 04｜Removed-setting no-gap rule

`LOCKED / USER EXPLICIT`

当 V4 移除一个旧设定时：

> **不能只删除文本。必须确认它原来承担的剧情、工程、人物或视觉功能由 V4 新机制完整接替。**

典型替换关系：

- 旧区域状态差异 → 本地公共时间的白天 / 黄昏 / 夜晚断层；
- 旧季末统一状态证明 → 剩余城区恢复一个可持续公共“现在”；
- 一次性重力奇观 → Local Gravity Frames 全季递进；
- 抽象群岛化 → 桥连接密度持续下降；
- 抽象 legacy branch → 旧城区 + 桥 / 服务 / 时间 / 重力 / 协议兼容栈；
- 泛化的城市内部深渊 → 嘉陵江这类有限、封闭、工程化巨构空腔。

任何新 Active 文档如果删除旧功能却没有给出 successor function，应视为迁移失败。

# 05｜Organic integration rule

`LOCKED / USER EXPLICIT`

> **尽可能有机结合。**

执行优先级：

1. 人物当前需求 / 公共动作；
2. 已经形成的跨集因果债；
3. 实际城市空间；
4. 时间 / 重力是否真的改变动作；
5. 最后才是视觉母题。

禁止把每集写成：

> 桥展示 + 时间异常 + 重力异常 + 嘉陵江奇观 + 主题对白。

某个世界设定只在它真实影响当前动作或后果时进入前景。

# 06｜TBD / unresolved detail

V4 区分：

- `LOCKED`：已确认事实；
- `LOCKED_DIRECTION`：功能 / 方向已确认，工程实现尚可优化；
- `EXECUTION_TBD`：Canon 已清楚，但对白、编号、UI、镜头、精确设备名等仍由 screenplay / visual execution 决定。

禁止：

- 用整理动作把未确认工程参数自动变成 Canon；
- 用旧文件里的具体编号覆盖 V4 未锁定的工程实现；
- 把 visual prompt 的临时写法提升成世界事实。
