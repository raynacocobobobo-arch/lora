# 01｜Episode function

EP01 不再是：

> 系统认为没人，男主进去发现一个系统漏掉的活人。

本集改为：

> **一条灾后遗留 occupancy record 仍显示某个居民留在 302；男主执行最终现场核销时确认这个人已经不在那里，记录确实过时。就在公共流程准备据此关闭旧状态并完成 302 旧支路 cutover 时，男主又发现：不仅人的记录过时，公共系统对 302 当前物理拓扑与 Local Gravity Frame 的理解也已经过时。**

本集真正回答：

> **过去曾经正确的记录，不能自动替代现在的现场。**

它建立男主整季职责：

> **present physical fact / execute-abort reality。**

---

# 02｜Why now / why male

302 位于嘉陵江附近老城区服务层。

T0 后它经历过：

- 临时避难；
- 通信与公共数据改线；
- 本地生命保障接管；
- 部分服务桥断开；
- Local Gravity Frame 本地维持；
- 后续公共模型多次重建。

现在城市准备结束一组已经不再使用的灾后临时状态，并把 302 相关旧支路重新并入/隔离到正式拓扑。

但系统里仍有一条未闭合的 occupancy record：

> **某居民最后状态 = 仍在 302。**

因为涉及潜在人身状态，公共程序不能仅凭远程数据直接核销。

所以必须有人做最后 physical clearance。

男主被派去，不是因为大家已经怀疑“里面还有人”，而是因为：

> **只有现场事实确认可以把这条历史记录正式关掉，并给后续 cutover 一个 execute / abort 条件。**

---

# 03｜Cold Open — 过时记录把他带到 302

目标时长：`0:00–0:25`

城市已在灾后恢复期。

男主进入旧服务层。

私人 AI 给出记录摘要：

- occupancy unresolved；
- 记录中的人最后一次确认在 302；
- 之后没有完整迁移闭环；
- 302 本身当前公共模型状态低可信。

私人 AI 的合理判断：

> 这是一次遗留状态核销，先完成人员确认，再退出。

不需要神秘感。

---

# 04｜Pressure 1 — 记录中的人不在

目标时长：`0:25–0:55`

男主进入允许检查的范围。

他没有找到记录中的人。

现场证据明确支持：

- 当前无人活动；
- 没有实时生命保障负载指向该居民；
- 没有新鲜人工使用痕迹；
- 本地可访问记录显示这名居民早已在某次后续转移中离开 / 状态终止，但该闭环没有同步回统一系统。

精确居民身份与后续去向不重要，可保持匿名。

结论：

> **occupancy record stale。**

私人 AI 与男主在这一步没有冲突。

---

# 05｜Trigger — 关闭错误记录以后，另一个错误才暴露

目标时长：`0:55–1:20`

男主准备提交：

> `OCCUPANCY CLEAR / HISTORICAL RECORD STALE`

公共 cutover 流程因此进入下一阶段。

这里必须明确：

> **不可逆机械分离尚未发生，但若干可回退的预处理已经开始。**

例如功能上包括：

- 服务负载转移；
- Gravity Handoff 卸载准备；
- 旧接口 reference 重新对齐；
- 结构锁进入待切换状态。

就在这些预处理发生时，男主观察到一个当前物理事实：

> **302 的真实重力方向 / 结构姿态与公共模型预计状态不一致。**

不是屏幕“报错”。

先由身体/物体看见：

- 液体偏向错误方向；
- 悬挂件与模型中的“下方”不一致；
- 维护件开始产生反常受力；
- 男主自己的身体感受到轻微方向偏转。

---

# 06｜Obstacle — 为什么不能按系统继续

公共系统并不是愚蠢。

它拥有的是：

> **基于旧拓扑与灾后同步结果形成的、曾经合理的 302 状态。**

实际 302 在长期本地维持中已经形成了一个稍有不同的 Local Gravity Frame / 结构姿态关系。

如果继续按旧模型完成 Gravity Handoff 卸载与接口切换：

> **系统会把一个并不处于预计姿态的真实结构，当成已经对齐的结构处理。**

风险不是“302里还有人”。

风险变成：

> **错误当前前提会让一个本可控的公共 cutover 真实伤到结构 / 人员。**

私人 AI 此时掌握更广风险，合理要求男主撤出，因为她也看见过渡正在变得不稳定。

她没有错。

---

# 07｜Choice / Dominant Turn — 暂停的不是未来，是错误当前前提

目标时长：`1:20–1:45`

男主只能做一件窄动作：

> **HOLD CUTOVER / PRESENT STATE CONFLICT。**

他没有权力：

- 宣布 302 永久保留；
- 定义城市未来边界；
- 推翻全部公共模型。

他只是确认：

> **记录中的人确实不在；但系统准备使用的 302 当前物理状态也不成立。**

因此这次不可逆动作不能继续。

Dominant Turn：

> **一个原本应该在现场核销后顺利结束的旧节点，被重新送回当前公共现实，因为现场证明“过去记录已过时，而系统对现在的物理模型也同样过时”。**

---

# 08｜Gravity Event — 同一任务的直接后果

目标时长：`1:45–2:10`

Extreme 级重力事件必须来自同一 causal chain。

不是事件结束后突然发生另一个事故。

推荐功能逻辑：

> cutover 的可回退预处理已经开始改变 Gravity Handoff 负载；男主在发现真实 frame mismatch 后中止不可逆步骤，但过渡系统需要时间退出已开始的状态，导致局部重力方向进一步偏转并短暂反转。

男主进入真实坠落危险。

女科长位于本次 cutover 的现场公共控制/安全位置，因为：

> **她本来就负责这次不可逆公共动作的授权与责任。**

她固定自己，使用维护锚点 / 安全索，在男主越过安全边界时：

> **真实抓住他。**

不由机器人替代。

# 10｜End Image — 城市尺度从身体事实打开

目标时长：`2:10–2:30`

男主被拉回安全结构。

随着重力方向与视角恢复，镜头第一次真正打开：

- 明确人工边界；
- 极远工程开口外的地球。

不是：

> 原来他们在太空。

而是：

> **原来“下方”“这里”“现在”都依赖一整套人工共同 reference 才能成立。**

不让角色说这句话。

# 11｜State Delta

EP01 持久变化：

1. 记录中“仍在 302 的居民”被正式确认是过时记录；本集没有救到该记录中的人。
2. 302 作为真实物理节点没有被按旧模型直接核销/切除，而是进入重新测绘、重力/结构 remap 与后续恢复链。
3. 男主第一次证明：当前现场事实可以阻止一个基于 stale state 的公共动作。
4. 女科长在身体层面救下男主，并在公共责任链中与他的现场事实发生第一次直接关系。
5. 302 因重新纳入当前公共模型，后续才有条件被维修、重新使用并在 EP09 成为一个真实有人生活的旧城区节点。
6. `DEBT_MALE_VALUE` 打开：男主把“只有我能在现场纠正过时现实”当成价值证明。
