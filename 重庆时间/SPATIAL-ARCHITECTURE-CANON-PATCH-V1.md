# 01｜One-sentence city definition

> **第二新重庆是一座经过长期扩建形成的环形船坞型太空城市：主城呈近似环形 / 甜甜圈总体形态，内部有效城市高度约 200 m、主环半径约 1 km；不同年代、不同规模的舱室与城区模块沿主环生长，并通过“桥”接入共同城市。**

Exact engineering dimensions remain `DESIGN DIRECTION`, not construction-grade numbers.

The audience should understand the city as one readable whole, not as an infinite stack of unrelated megastructures.

---

# 02｜Why it looks like a shipyard

第二新重庆不是一次性建成的完美空间站。

它经历了长期建设、扩建、换代、维修与模块替换，因此城市天然存在：

- 不同年代的舱段；
- 不同尺度的生活 / 公共 / 工业模块；
- 新旧接口标准并存；
- 可拆换或追加的附属舱室；
- 大量桥接结构；
- 明显但克制的历史拼接痕迹。

核心空间感觉：

> **城市像一座长期使用中的大型船坞：它能制造、接驳、替换、隔离并最终释放不同规模的城市舱段。**

这解释了为什么 302 可以真实存在、长期可居住，同时仍保留大量 legacy compatibility。

# 03｜Five spatial families only

第一季不再无限增加一级大区。

## A｜主环生活区 / Main Ring Living City

观众理解中的“正常重庆”。

包含：

- 住宅；
- 商业；
- 医院；
- 普通街道；
- 轨道站；
- 婚礼 / 公共活动空间；
- 行政与公共服务节点。

它不需要被工程化拆成很多独立城市层。

---

## B｜中央共享区 / Shared Civic-Utility Belt

位于主环内部面与主要桥接空间附近。

包含：

- 高等级公共换接；
- 热储能 / 环境换热；
- Shared Hub；
- 轨道 / 能源 / 数据接口；
- Gravity Handoff 公共设施。

EP06、EP07 主要使用这一空间家族。

---

## C｜旧模块区 / Legacy Module Belt

长期扩建中保留下来的旧城市模块群。

特点：

- 仍可正常生活；
- 设备和协议年代更老；
- Local Operation 比较深；
- 维护与兼容成本高；
- 与新公共主环之间依赖桥接和 legacy mapping。

**302 固定属于这一空间家族。**

302 不是一栋楼，而是一个小型旧城区 / 旧舱段集群。

---

## D｜桥接带 / Bridge Connection Family

不是一个独立城区，而是第二新重庆真正的城市组织系统。

包括：

- 城市主干桥；
- 区域桥；
- 服务桥；
- 维护生命线；
- 舱段接口桥；
- 轨道 / 环境 / 重力过渡连接。

桥可以同时承担交通、结构、服务和共同状态连接。

---

## E｜外缘维护区 / Outer Maintenance Edge

主环和外接模块靠近真空边界的工程区域。

包含：

- EVA 接口；
- 外部维修固定点；
- 小型附属维护舱；
- 外缘接口结构；
- 可释放 / 可隔离的工程连接段。

EP01 的事故出口发生在 302 邻接的这一空间家族。

# 04｜Bridge definition — one mechanism, many scales

`LOCKED`

> **桥 = 模块与模块之间的可识别连接。**

它不是只供人走的桥面。

一条桥 / 接口连接可以组合承担：

1. 人员与货物通行；
2. 结构锚定；
3. 能源与环境介质；
4. 数据与协议；
5. Local Public Time reference handoff；
6. Local Gravity Frame / Gravity Handoff；
7. 公共授权与运行状态的跨区连接。

因此：

> **断桥 = 某一组连接从共同城市中退出。**

它可以发生在不同尺度：

- EP01：小型外缘附属接口段意外脱离；
- EP02：大型主干桥被迫退出；
- EP10：熟悉、健康、仍有价值的旧连接被主动结束。

这三者构成同一空间语法的递进，而不是三个互不相关的事故。

# 05｜Jialing / 嘉陵江 — simplified spatial reading

保留 `嘉陵江` 作为第二新重庆最重要的公共地理称呼，但不再要求它表现为无限深的垂直巨构峡谷。

新版方向：

> **嘉陵江是主环内部最宽、桥最密、共享设施最集中的连续开放结构带 / 船坞式城市空腔。**

它可以沿环形主城弯曲延伸。

居民仍自然使用：

- 过江；
- 江桥；
- 江这边 / 江对面；
- 上游 / 下游；
- 临江区。

视觉识别仍保留：

> **一眼可见多条不同尺度的桥和舱段接口。**

但空间必须可读、有限、正常，不依赖“上方还有无数层城市”的奇观。

# 06｜No multi-layer traversal rule

`LOCKED`

> **城市可以在视觉上有上下错层和多桥关系，但角色行动不默认穿越多层城市。**

每集主动作原则：

> **1 个主区域 + 1 个相邻接口 / 连接；必要时再进入 1 个明确子区域。**

跨区域必须通过观众可理解的：

- 桥；
- 轨道；
- 舱门 / 接口；
- 维护连接。

不得依靠抽象的“继续往下几层 / 往上几层”把人物送到另一个城区。

# 07｜302 spatial lock

`LOCKED_DIRECTION`

302 位于：

> **Legacy Module Belt 的外缘位置，并与 Outer Maintenance Edge 相邻。**

因此 302 同时具有：

- 正常生活区；
- 旧公共区；
- Gravity Service / legacy relay；
- 外缘维护接口。

但这些都是同一个旧模块集群内的子空间，不是四座上下叠压的城市。

EP01 动线应始终可压缩为：

> **主环正常城市 → 302 → 302维修 / 重力接口 → 外缘附属接口段 → 太空。**

观众不需要学习完整外壳剖面。

# 08｜EP01 detachment mechanism — reverse bridge operation

`LOCKED_DIRECTION / replaces over-engineered shell traversal`

EP01 事故的空间本质调整为：

> **一次小尺度“断桥 / 断接”的意外版本。**

男主所在位置不是 302 主体本身，而是：

> **302 外缘一段小型附属接口结构 / 维护过渡段。**

正常情况下，它仍属于 302 的连接世界，并由结构锁、服务连接与 Gravity reference 共同维持。

EP01 causality remains:

1. routine Gravity Reference Reset；
2. trusted public/local handshake failure；
3. partial handshake reveals `302 LOCAL = PUBLIC + 08:00`；
4. safe reset window already expired；
5. gravity vector instability begins；
6. full handshake eventually succeeds；
7. AI refuses lethal immediate nominal restore；
8. AI routes male to the outer safe-reset / securing point；
9. Plan B genuinely begins to work；
10. a T0 latent structural/interface scar propagates under abnormal loading；
11. **the supporting interface segment itself loses its valid structural connection / releases from the main city connection**；
12. male + a small attached piece of structure drift away from the ring city；
13. AI can stabilize/reduce motion but cannot return him with available EVA capability.

Important:

> **302 本体没有脱离。**

Only a small outer interface / attached maintenance segment detaches.

This preserves EP04, EP09 and EP10's need for 302 to remain real, inhabited and operable.

# 09｜T0 relation

T0 does not need a detailed shell engineering model.

For story purposes, T0 left four relevant classes of scar:

- structural / interface damage；
- bridge and service reroutes；
- public/local time-reference degradation；
- gravity / protocol compatibility scars.

The important consequence is not “there is a hole in the hull.”

It is:

> **the city survived by keeping more modules locally alive and more connections conditionally compatible.**

That directly produces the Preservation Paradox.

---

# 10｜City-scale state model

Physical region names stay stable; state changes are overlays.

Recommended operational states:

- `CONNECTED` — normal common-city connection；
- `LOCAL OPERATION` — local system healthy, shared reference degraded；
- `DEGRADED LOCAL` — local life continues with reduced public capability；
- `CONTESTED / TRANSITION` — interface or public connection under special handling；
- `MIGRATION` — residents/services moving out of future retained framework；
- `SERVICE ONLY` — people cleared, old connection kept temporarily for cutover；
- `RETIRED / OUTSIDE COMMON CITY` — structure may physically remain but no longer belongs to retained public operating city.

This prevents every episode from inventing a new city region just because a familiar place changes state.

---

# 11｜Visual simplification rules

1. The city should read as one ring/shipyard whole before it reads as an engineering diagram.
2. Do not require the audience to understand shell thickness or dozens of infrastructure layers.
3. Different ages of modules should be legible through scale, materials, interface language and maintenance traces.
4. Bridges and connector hardware are recurring visual anchors.
5. Multi-level space is allowed as composition, not as mandatory geography.
6. The ring interior can contain large open spans, but they remain finite and readable.
7. Exterior space is rare; EP01's drift gains weight because normal city life is predominantly enclosed.

---

# 12｜Replacement / no-gap mapping

Old function → New mechanism:

- `infinite/multi-layer megacity feeling` → **finite ring city + modules of different ages/scales + multiple bridges visible at once**；
- `deep layered route to outer hull` → **302 directly neighbors outer maintenance edge**；
- `complex shell traversal` → **one clear outer interface**；
- `gravity escape through many city layers` → **gravity instability inside one 302 interface path**；
- `safe point structure breaks generically` → **T0-scarred outer interface segment loses structural connection / detaches, a small-scale reverse bridge event**；
- `bridge as recurring metaphor only` → **bridge as literal module-connection technology at all scales**；
- `Jialing as near-infinite canyon` → **wide, finite, bridge-dense shared open/shipyard corridor within the ring**.

No story function should depend on the superseded over-engineered spatial stack.
